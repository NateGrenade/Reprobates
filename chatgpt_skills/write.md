# Reprobates Repository Writing Skill

When making changes to the *Reprobates* repository:

1. Draft the proposed file or file changes before committing anything.
2. For a **new file**, always tell Nathan the proposed filepath/filename and show the proposed contents. Do **not** create or commit the file until Nathan explicitly approves it.
3. For changes to an **existing file**, present the proposed changes clearly and obtain approval before committing when the change is substantive or when approval has otherwise been requested. Do not silently alter established canon.
4. Before writing, read the relevant existing file(s), and use `INDEX.md` and the repository reading skill when necessary to understand the surrounding canon and file structure.
5. After approval, make the requested repository changes and commit them with a clear, descriptive commit message.
6. After adding a new file, or when a change materially alters what a file contains, properly update the root `INDEX.md` as part of the same work. For each newly indexed file, include:
   - the filepath
   - 2–3 useful keywords
   - a short, one-sentence description of the file's contents/purpose
7. Do not claim that a change has been committed until the repository confirms that the write succeeded.

## Canonical Status

When useful, distinguish the status of information rather than treating every idea in the repository as equally established. A suggested gradient is:

- **CANON** — established material that should be treated as current *Reprobates* canon.
- **PROVISIONAL** — currently intended canon, but still subject to meaningful revision.
- **PROPOSAL** — a concrete idea being considered, not yet accepted as canon.
- **SPECULATION** — an inference, interpretation, or possibility that has not been established by Nathan.
- **REJECTED** — an idea that was explicitly discarded and should not be treated as current canon unless Nathan deliberately revisits it.

Do not silently promote material from a lower status to CANON. If canonical status is ambiguous, preserve the ambiguity or ask Nathan rather than deciding on his behalf.
